# فاز ۸: اعتبارسنجی انتقال پارسیان

## مرز صداقت محصول

وجود نام پارسیان، کد حساب مقصد یا CSV متوازن به معنی ورود مستقیم نیست. حساب‌یار تا وقتی قالب واقعی همان نسخه و نتیجهٔ ورود روی یک شرکت آزمایشی ثبت نشده باشد، خروجی را «سازگار مستقیم» معرفی نمی‌کند و فایل `.bak` نمی‌سازد.

## جریان آزمون

1. حسابدار بستهٔ ثابت فاز ۷ را می‌سازد و SHA-256 آن را نگه می‌دارد.
2. نسخهٔ دقیق پارسیان و یک برچسب غیرمحرمانه برای شرکت آزمایشی ثبت می‌شود.
3. Dry Run می‌تواند خطای ستون، کد حساب، تاریخ یا واحد پول را ثبت کند؛ موفقیت آن مجوز پذیرش نهایی نیست.
4. در `trial-import` واقعی، تعداد ردیف واردشده، تعداد ردیف ردشده و جمع بدهکار/بستانکار مقصد ثبت می‌شود.
5. نتیجهٔ موفق فقط وقتی ذخیره می‌شود که تعداد ردیف با بسته برابر، ردیف ردشده صفر و هر دو جمع دقیقاً منطبق باشند.
6. بستهٔ پارسیان فقط پس از همین آزمون موفق می‌تواند به وضعیت «ورود تأیید شد» برسد.

## داده‌های ممیزی

هر آزمون شامل شناسهٔ batch، نرم‌افزار و نسخه، شرکت آزمایشی، نوع تلاش، نتیجه، واحد مبلغ، تعداد ردیف‌ها، جمع‌ها، خلاصهٔ خطا، یادداشت، آزمون‌کننده و زمان است. خود فایل خروجی تغییر نمی‌کند و آزمون به همان digest متصل می‌ماند.

## گام وابسته به دادهٔ واقعی

برای ساخت adapter نسخه‌محور باید یکی از این ورودی‌ها فراهم شود:

- قالب رسمی import/export از همان نسخهٔ پارسیان؛
- مستندات schema یا API رسمی؛
- نمونهٔ خروجی واقعی و پاک‌سازی‌شده از شرکت آزمایشی؛
- فایل `.bak` نمونه فقط برای بررسی ایزوله با نسخهٔ دقیق SQL Server و مجوز روشن.

تا قبل از آن، فاز ۸ فرایند آزمون و شواهد را کامل می‌کند، نه سازگاری را جعل.
