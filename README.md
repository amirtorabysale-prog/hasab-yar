# حساب‌یار ۲ — دفتر مالی صوتی

PWA فارسی و موبایل‌اول برای ثبت دریافت و پرداخت با صدا یا متن. هر جمله ابتدا به تراکنش‌های ساخت‌یافته تبدیل می‌شود و فقط پس از بازبینی مبلغ، نوع و دسته توسط کاربر در پایگاه‌داده ثبت می‌شود.

حساب‌یار در نسخه فعلی «دفتر مالی صوتی و دستیار مدیریت نقدینگی» است، نه نرم‌افزار حسابداری رسمی. عددهای خلاصه بر پایه دریافت و پرداخت‌های ثبت‌شده‌اند و جایگزین صورت مالی، دفتر قانونی یا محاسبه سود حسابداری نیستند. محدوده محصول در [docs/product-scope.md](docs/product-scope.md) و قواعد صحت مالی و مهاجرت حساب‌ها در [docs/accounting-integrity.md](docs/accounting-integrity.md) ثبت شده است.

## قابلیت‌ها

- رابط کامل RTL با فونت Vazirmatn و طراحی دفتر حساب مدرن
- ثبت یک یا چند تراکنش از یک جمله فارسی
- پشتیبانی از عددهای فارسی، عددهای حروفی، تومان و تبدیل ریال به تومان
- تشخیص زندهٔ فارسی در مرورگر و نمایش متن و مبلغ هم‌زمان با صحبت
- پارس قطعی و محلی مبلغ‌های رسمی و محاوره‌ای؛ بدون انتظار برای هوش مصنوعی
- مقایسهٔ چند برداشت موتور صدا و هشدار اجباری هنگام اختلاف مبلغ
- مسیر اصلی `gpt-transcribe` فارسی، پارسر قطعی مبلغ و Gemini به‌عنوان پشتیبان
- اندازه‌گیری زمان پاسخ، نرخ موفقیت و تعداد اصلاح‌های صوت برای بهبود واقعی دقت
- کارت تأیید مبلغ، نوع، دسته، هشدار مبلغ غیرعادی و گزینه‌های جایگزین
- رابط واکنش‌گرا برای موبایل و ویندوز با ناوبری دسکتاپ و دکمهٔ صوت چسبیده
- دفتر تراکنش قابل جست‌وجو، ویرایش و حذف نرم با سابقهٔ حسابرسی
- اشخاص، طلب و بدهی، سررسید و تسویهٔ خودکار در دفتر
- هزینه و درآمد دوره‌ای، فاکتور قابل چاپ و وصول مستقیم
- بستن صندوق روزانه و محاسبه اختلاف موجودی
- نگهداری خصوصی عکس رسید و استخراج مبلغ پیشنهادی از توضیح فارسی
- موجودی سبک کالا با ورود/خروج و هشدار کمبود
- پرسش فارسی از دادهٔ مالی با پاسخ قطعی و بدون ساختن عدد خیالی
- دو تجربه متمایز شخصی و کسب‌وکار، هشدار نقدینگی و تخمین دوام موجودی
- خروجی پشتیبان JSON برای مهاجرت و نگهداری امن داده
- ذخیره پایدار در SQLite و API واقعی برای تمام جریان‌های مالی
- ورود مالک با رمز هش‌شده، نشست HttpOnly و محدودیت تلاش ناموفق
- یادگیری دسته‌بندی از اصلاح کاربر و مدیریت نگاشت‌ها
- گزارش هفتگی، ماهانه و سه‌ماهه بدون نمودارهای شلوغ
- نصب به‌شکل PWA و صف ثبت/ضبط در حالت آفلاین
- CI برای اجرای تست‌ها و Build در هر Pull Request

## اجرا

نیازمندی: Node.js نسخه ۲۲٫۵ یا جدیدتر.

```bash
npm install
cp .env.example .env
npm run dev
```

رابط توسعه روی `http://localhost:5173` و API روی `http://localhost:4173` اجرا می‌شود.

پیش از اجرا مقدارهای `ADMIN_USERNAME` و `ADMIN_PASSWORD` را در `.env` عوض کنید. رمز باید حداقل ۱۲ نویسه و غیرقابل حدس باشد؛ هیچ مسیر ثبت‌نام عمومی وجود ندارد و اولین مالک فقط از متغیر محیطی سرور ساخته می‌شود.

برای Build تولیدی:

```bash
npm run build
npm start
```

## مسیر سریع و دقیق صدا

در Chrome و مرورگرهای سازگار، Web Speech API متن فارسی را زنده تولید می‌کند. حساب‌یار همان لحظه عدد را روی دستگاه کاربر پارس می‌کند و معمولاً حدود نیم ثانیه بعد از رهاکردن دکمه کارت تأیید را نشان می‌دهد. ضبط حداکثر ۱۲ ثانیه است و اگر کاربر دکمه را خیلی زود رها کند نیز ضبط به‌طور قطعی بسته می‌شود.

اگر تشخیص زندهٔ مرورگر قابل اعتماد باشد، نتیجه بدون ارسال صوت آماده می‌شود. در غیر این صورت فایل WAV کوتاه به سرور می‌رود: ابتدا `gpt-transcribe` گفتار فارسی را پیاده می‌کند، سپس پارسر قطعی حساب‌یار مبلغ، نوع و دسته را استخراج می‌کند. مدل زبانی اجازه ندارد مبلغ تراکنش را مستقیماً ثبت کند. اگر OpenAI در دسترس نباشد، Gemini مسیر پشتیبان است. کل پردازش زمان‌دار و قابل لغو است.

## فعال‌سازی صدا روی Railway

در بخش Variables سرویس، این متغیرها را تنظیم کنید:

```env
OPENAI_API_KEY=your_server_side_key
OPENAI_TRANSCRIBE_MODEL=gpt-transcribe
GEMINI_API_KEY=your_server_side_key
GEMINI_MODEL=gemini-3.7-flash
VOICE_PROVIDER_ORDER=openai,gemini
```

کلیدها هرگز وارد مرورگر یا Build نمی‌شوند. بدون `OPENAI_API_KEY` برنامه خودکار به Gemini می‌رود؛ بدون هر دو کلید، ورود دستی و تشخیص زندهٔ سازگار مرورگر همچنان کار می‌کند.

برای ماندگاری داده در Railway یک Volume بسازید، آن را مثلاً روی `/data` متصل کنید و مقدار زیر را قرار دهید:

```env
DATABASE_PATH=/data/hesab-yar.sqlite
```

بدون Volume، دادهٔ SQLite ممکن است با Deploy بعدی از بین برود.

## داده و حریم خصوصی

مسیر پیش‌فرض پایگاه‌داده `data/hesab-yar.sqlite` است و در Git ذخیره نمی‌شود. برای پیش‌نمایش اختیاری می‌توان `SEED_DEMO=true` را تنظیم کرد یا یک‌بار `npm run seed` را اجرا کرد. در حالت عادی دیتابیس خالی و آماده داده واقعی کاربر است.

برای محیط واقعی، مسیر `data` باید روی دیسک پایدار سرویس میزبانی قرار گیرد. نشست ورود با Cookie امن و SameSite محافظت می‌شود. پیش از عرضه عمومی نیز رمزنگاری نسخه پشتیبان، سیاست نگهداری فایل صوتی و رضایت‌نامه حریم خصوصی باید نهایی شود.

مبالغ نسخه ۱ در پایگاه داده به تومان ذخیره می‌شوند. مقصد هسته حسابداری آینده ذخیره به ریال و نمایش انتخابی تومان است؛ این تغییر فقط با migration نسخه‌بندی‌شده انجام می‌شود تا معنای داده‌های موجود تغییر نکند.

## تست

```bash
npm test
npm run build
```

تست‌ها تبدیل ارقام فارسی/عربی، اعداد رسمی و محاوره‌ای، اعشار، جمله چندتراکنشی، ریال به تومان، دسته‌بندی آموخته‌شده، درخواست درست `gpt-transcribe`، اختلاف برداشت‌های موتور صدا، ویرایش امن تراکنش، تسویهٔ طلب و وصول فاکتور را پوشش می‌دهند. مجموعه‌ای از جمله‌های واقعی فارسی نیز به‌عنوان آزمون رگرسیون سرعت و دقت اجرا می‌شود.
