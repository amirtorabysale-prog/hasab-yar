# حساب‌یار ۲ — دفتر مالی صوتی

PWA فارسی و موبایل‌اول برای ثبت دریافت و پرداخت با صدا یا متن. هر جمله ابتدا به تراکنش‌های ساخت‌یافته تبدیل می‌شود و فقط پس از بازبینی مبلغ، نوع و دسته توسط کاربر در پایگاه‌داده ثبت می‌شود.

حساب‌یار در نسخه فعلی «دفتر مالی صوتی و دستیار مدیریت نقدینگی» با دفتر کل دوطرفه، چرخهٔ فاکتور، تطبیق بانکی، انبار دائمی و مالیات قابل‌تنظیم است، نه نرم‌افزار حسابداری رسمی. خلاصه‌های روزانه همچنان بر پایه دریافت و پرداخت هستند و جایگزین صورت مالی، دفتر قانونی یا محاسبه سود تعهدی کامل نیستند. محدوده محصول در [docs/product-scope.md](docs/product-scope.md)، قواعد صحت مالی در [docs/accounting-integrity.md](docs/accounting-integrity.md)، [حافظهٔ مالی و هشدارهای قابل اقدام](docs/financial-memory-and-alerts.md)، هسته دفتر کل در [docs/double-entry-ledger.md](docs/double-entry-ledger.md)، چرخهٔ فاکتور در [docs/invoicing-and-receivables.md](docs/invoicing-and-receivables.md)، تطبیق بانک در [docs/bank-reconciliation.md](docs/bank-reconciliation.md)، انبار و بهای تمام‌شده در [docs/inventory-and-cogs.md](docs/inventory-and-cogs.md)، مالیات مدیریتی در [docs/tax-and-vat.md](docs/tax-and-vat.md)، تنظیمات امنیتی در [docs/security-hardening.md](docs/security-hardening.md)، معماری دفترها و نقش‌ها در [docs/workspaces-and-roles.md](docs/workspaces-and-roles.md) و روش پشتیبان‌گیری در [docs/backup-and-recovery.md](docs/backup-and-recovery.md) ثبت شده است.

اولویت‌های توسعه، قابلیت‌های متوقف‌شده و معیار پذیرش هر فاز در [نقشهٔ اجرایی محصول](docs/product-roadmap.md) ثبت شده‌اند. جریان کنترل‌شدهٔ آزمون مقصد در [اعتبارسنجی انتقال پارسیان](docs/phase-8-parsian-validation.md) توضیح داده شده است.

مسیر فعلی محصول به سمت مشتری «دفتر حسابداری» و ترتیب یازده فاز بعدی در [نقشهٔ فازبندی‌شدهٔ دفتر حسابداری](docs/firm-roadmap.md) آمده است. فاز ۱ (میز کار دفتر حسابداری)، فاز ۲ (کدینگ استاندارد، تفصیلی شناور و مرکز هزینه) و فاز ۵ (پل دوطرفهٔ اکسل و پارسیان) اجرا شده‌اند.

قرارداد بستهٔ حسابدار، پلن‌ها، متریک‌های پایلوت و runbook رخداد در [مستند فاز ۶](docs/phase-6-pilot-and-operations.md) آمده است.

## قابلیت‌ها

- رابط کامل RTL با فونت Vazirmatn و طراحی دفتر حساب مدرن
- ثبت یک یا چند تراکنش از یک جمله فارسی
- پشتیبانی از عددهای فارسی، عددهای حروفی، تومان و تبدیل ریال به تومان
- تشخیص زندهٔ فارسی در مرورگر و نمایش متن و مبلغ هم‌زمان با صحبت
- پارس قطعی و محلی مبلغ‌های رسمی و محاوره‌ای؛ بدون انتظار برای هوش مصنوعی
- مقایسهٔ چند برداشت موتور صدا و هشدار اجباری هنگام اختلاف مبلغ
- مسیر اصلی `gpt-transcribe` فارسی، پارسر قطعی مبلغ و Gemini به‌عنوان پشتیبان
- اندازه‌گیری زمان پاسخ، نرخ موفقیت و تعداد اصلاح‌های صوت برای بهبود واقعی دقت
- کارت تأیید مبلغ، نوع، دسته، هشدار مبلغ غیرعادی و گزینه‌های جایگزین
- رابط واکنش‌گرا برای موبایل و ویندوز با ناوبری دسکتاپ و دکمهٔ صوت چسبیده
- دفتر تراکنش قابل جست‌وجو، ویرایش و حذف نرم با سابقهٔ حسابرسی
- ثبت خودکار دوطرفه، تراز آزمایشی، اسناد معکوس و بستن دورهٔ ماهانه شمسی
- اشخاص، طلب و بدهی، سررسید و تسویهٔ خودکار در دفتر
- هزینه و درآمد دوره‌ای، فاکتور فروش/خرید، پیش‌نویس، صدور، دیرکرد و تسویهٔ مرحله‌ای
- ورود CSV بانک با تشخیص قالب/ستون، پیشنهاد تطبیق توضیح‌دار، ثبت اختلاف و کنترل ماندهٔ بانک با دفتر
- میز کار دفتر حسابداری: وضعیت فوریت‌محور همهٔ پرونده‌های همان کاربر در یک صفحه با ایرادهای بازدارنده، کارهای در انتظار کنترل و ورود مستقیم به هر پرونده
- خروجی اکسل (xlsx) و CSV با قالب ستونی دلخواه دفتر، واحد تومان یا ریال و شیت شناسنامه؛ ورود کدینگ، تفصیلی و ماندهٔ افتتاحیه از اکسل یا پارسیان
- کدینگ گروه/کل/معین دفتر با ورود CSV فارسی، نگاشت خودکار پیشنهادی حساب‌های حساب‌یار، تفصیلی شناور و مرکز هزینه روی آرتیکل سند و گزارش گردش هر بعد
- پل تحویل حسابدار با CSV ردیف‌های دفتر کل، مبلغ تومان/ریال، نگاشت کد حساب مقصد، SHA-256 و سابقهٔ تأیید/رد
- بستن صندوق روزانه و محاسبه اختلاف موجودی
- OCR عکس رسید، صندوق بازبینی، توضیح صوتی و اتصال کنترل‌شده به ثبت دفتر یا ردیف بانک
- انبار دائمی با میانگین موزون، ارزش موجودی، بهای تمام‌شده فروش و هشدار کمبود
- نرخ مالیاتی قابل‌تنظیم در هر ردیف فاکتور، تفکیک مشمول/نرخ صفر/معاف و گزارش مالیات فروش و اعتبار خرید
- پرسش فارسی از دادهٔ مالی با بازه، واحد، فرمول و لینک تمام منابع سازندهٔ عدد
- یک هشدار اولویت‌دار در «امروز»، هشدارهای توضیح‌پذیر با حساسیت قابل تنظیم و تعویق ۲۴ ساعته
- سه سناریوی دوام نقدینگی بدون فرض درآمد آینده
- بستهٔ پایان ماه حسابدار، صندوق درخواست توضیح و همکاری منبع‌محور صاحب کسب‌وکار/حسابدار
- پلن و سهمیهٔ شفاف برای providerهای پولی، بدون قطع ثبت دستی یا تایپ Chrome
- داشبورد هزینه و بودجهٔ هر دفتر، ثبت مصاحبهٔ پایلوت و پایش ماندگاری هفتهٔ چهارم
- دو تجربه متمایز شخصی و کسب‌وکار، هشدار نقدینگی و تخمین دوام موجودی
- پشتیبان رمزگذاری‌شدهٔ نسخه‌دار، بازبینی پیش از بازیابی و نقطهٔ بازگشت خودکار
- ذخیره پایدار در SQLite و API واقعی برای تمام جریان‌های مالی
- ورود مالک با رمز هش‌شده، نشست HttpOnly و محدودیت تلاش ناموفق
- چند دفتر کاملاً جدا، اعضای تیم و نقش‌های مالک، مدیر، حسابدار و فقط مشاهده
- یادگیری دسته‌بندی از اصلاح کاربر و مدیریت نگاشت‌ها
- گزارش هفتگی، ماهانه و سه‌ماهه بدون نمودارهای شلوغ
- نصب به‌شکل PWA و صف ثبت/ضبط در حالت آفلاین
- CI برای اجرای تست‌ها و Build در هر Pull Request

## اجرا

نیازمندی: Node.js نسخه ۲۲٫۵ یا جدیدتر.

```bash
npm install
cp .env.example .env
npm run dev
```

رابط توسعه روی `http://localhost:5173` و API روی `http://localhost:4173` اجرا می‌شود.

پیش از اجرا مقدارهای `ADMIN_USERNAME` و `ADMIN_PASSWORD` را در `.env` عوض کنید. رمز باید حداقل ۱۴ نویسه، دارای حرف و عدد و غیرقابل حدس باشد؛ هیچ مسیر ثبت‌نام عمومی وجود ندارد و اولین مالک فقط از متغیر محیطی سرور ساخته می‌شود.

برای Build تولیدی:

```bash
npm run build
npm start
```

## مسیر سریع و دقیق صدا

در Chrome، Web Speech از ابتدای ضبط برای نمایش فوری متن شروع می‌شود و حساب‌یار هم‌زمان track میکروفن را با WebRTC به `gpt-live-transcribe` متصل می‌کند. با رسیدن اولین delta معتبر، Realtime جای متن موقت مرورگر را می‌گیرد. عدد همان لحظه روی دستگاه کاربر پارس می‌شود و بعد از رهاکردن دکمه متن نهایی برای کارت تأیید commit می‌شود. کلید OpenAI هرگز به مرورگر داده نمی‌شود. ضبط حداکثر ۱۲ ثانیه است.

اگر Realtime برقرار نشود، Web Speech فقط پشتیبان نمایش زنده است. در صورت متن ناتمام یا نامعتبر، فایل WAV کوتاه به سرور می‌رود: ابتدا `gpt-transcribe` گفتار فارسی را پیاده می‌کند، سپس پارسر قطعی حساب‌یار مبلغ، نوع و دسته را استخراج می‌کند. مدل زبانی اجازه ندارد مبلغ تراکنش را مستقیم ثبت کند. اگر OpenAI در دسترس نباشد، Gemini مسیر پشتیبان فایل است.

قواعد تصمیم مسیر سریع، کنترل سکوت و اعداد غیرمالی، معیارهای کیفیت و متریک‌های `fastPathRate` در [معماری ثبت صوتی](docs/voice-entry.md) مستند شده‌اند.

## فعال‌سازی صدا روی Railway

در بخش Variables سرویس، این متغیرها را تنظیم کنید:

```env
OPENAI_API_KEY=your_server_side_key
OPENAI_TRANSCRIBE_MODEL=gpt-transcribe
OPENAI_REALTIME_TRANSCRIBE_MODEL=gpt-live-transcribe
OPENAI_REALTIME_TRANSCRIBE_DELAY=low
RECEIPT_OCR_MODEL=gpt-5.4-mini
GEMINI_API_KEY=your_server_side_key
GEMINI_MODEL=gemini-3.7-flash
VOICE_PROVIDER_ORDER=openai,gemini
DEFAULT_WORKSPACE_PLAN=free
OPENAI_TRANSCRIBE_USD_PER_MINUTE=
OPENAI_REALTIME_USD_PER_MINUTE=
GEMINI_AUDIO_USD_PER_MINUTE=
OPENAI_OCR_USD_PER_IMAGE=
```

کلیدها هرگز وارد مرورگر یا Build نمی‌شوند. `OPENAI_API_KEY` علاوه بر صدا، OCR رسید را نیز فعال می‌کند؛ مدل OCR را می‌توان با `RECEIPT_OCR_MODEL` تغییر داد. اگر OCR تنظیم نباشد یا خطا بدهد، تصویر حذف نمی‌شود و با توضیح کاربر در صندوق بازبینی می‌ماند. بدون کلیدهای صدا، ورود دستی و تشخیص زندهٔ سازگار مرورگر همچنان کار می‌کند.

`gpt-live-transcribe` در tier رایگان پشتیبانی نمی‌شود. کلید Railway باید متعلق به پروژه‌ای با اعتبار فعال و Limits کافی باشد. وضعیت را در [Limits پروژه](https://platform.openai.com/settings/organization/limits) بررسی کنید. حساب‌یار خطای موقت 429 را مطابق `Retry-After` متوقف می‌کند؛ اگر خطا از اعتبار/بودجه باشد، تلاش‌های OpenAI را برای ۳۰ دقیقه متوقف و مسیر Chrome/Gemini را حفظ می‌کند تا درخواست تکراری و بی‌فایده ساخته نشود.

نرخ‌های هزینه اختیاری‌اند و باید از صورتحساب واقعی provider وارد شوند. اگر خالی باشند، مصرف ثبت می‌شود اما داشبورد صریحاً اعلام می‌کند که جمع هزینه کامل نیست؛ حساب‌یار نرخ یا قیمت ساختگی فرض نمی‌کند.

برای ماندگاری داده در Railway یک Volume بسازید، آن را مثلاً روی `/data` متصل کنید و مقدار زیر را قرار دهید:

```env
DATABASE_PATH=/data/hesab-yar.sqlite
BACKUP_DIR=/data/backups
BACKUP_ENCRYPTION_KEY=a-unique-random-secret-with-at-least-32-characters
BACKUP_RETENTION_DAYS=14
```

بدون Volume، دادهٔ SQLite ممکن است با Deploy بعدی از بین برود.

`BACKUP_ENCRYPTION_KEY` فقط در Variables سرور قرار می‌گیرد و نباید با رمز ورود یا رمز فایل دانلودی یکی باشد. حساب‌یار تقریباً روزی یک پشتیبان رمزگذاری‌شده از هر دفتر می‌سازد، پس از نوشتن آن را واقعاً رمزگشایی و اعتبارسنجی می‌کند و نسخه‌های قدیمی‌تر از بازهٔ نگهداری را پاک می‌کند. راهنمای آزمون بازیابی و نگهداری امن کلید در [docs/backup-and-recovery.md](docs/backup-and-recovery.md) آمده است.

## داده و حریم خصوصی

مسیر پیش‌فرض پایگاه‌داده `data/hesab-yar.sqlite` است و در Git ذخیره نمی‌شود. برای پیش‌نمایش اختیاری می‌توان `SEED_DEMO=true` را تنظیم کرد یا یک‌بار `npm run seed` را اجرا کرد. در حالت عادی دیتابیس خالی و آماده داده واقعی کاربر است.

برای محیط واقعی، کل پوشهٔ `data` باید روی دیسک پایدار سرویس میزبانی قرار گیرد؛ دیتابیس دفتر اصلی کنار فایل کنترل و دفترهای بعدی در `data/workspaces` قرار می‌گیرند. نشست ورود با Cookie امن و SameSite محافظت می‌شود. فایل صوتی فقط برای تبدیل گفتار پردازش می‌شود و در سرور ذخیره نمی‌شود. تصویر رسید برای استخراج ساختاریافته به ارائه‌دهندهٔ OCR ارسال و سپس تا حذف دستی در دفتر نگه‌داری می‌شود؛ هیچ پیشنهاد OCR بدون تأیید کاربر ثبت مالی نمی‌سازد. حذف تصویر، تراکنش مالی مرتبط را تغییر نمی‌دهد. پیش از عرضه عمومی، متن حقوقی رضایت و حریم خصوصی متناسب با کشور محل عرضه باید بازبینی شود.

مبالغ نسخه ۱ در پایگاه داده به تومان ذخیره می‌شوند. مقصد هسته حسابداری آینده ذخیره به ریال و نمایش انتخابی تومان است؛ این تغییر فقط با migration نسخه‌بندی‌شده انجام می‌شود تا معنای داده‌های موجود تغییر نکند.

## تست

```bash
npm test
npm run build
```

تست‌ها تبدیل ارقام فارسی/عربی، اعداد رسمی و محاوره‌ای، اعشار، جمله چندتراکنشی، ریال به تومان، دسته‌بندی آموخته‌شده، درخواست درست `gpt-transcribe`، اختلاف برداشت‌های موتور صدا، ویرایش امن تراکنش، تسویهٔ طلب و وصول فاکتور را پوشش می‌دهند. توازن بدهکار و بستانکار، میانگین موزون موجودی، بهای تمام‌شده، مالیات ردیفی پس از تخفیف، اعتبار مالیات خرید، نرخ صفر/معاف، snapshot نرخ تاریخی، جلوگیری از فروش بیش از موجودی، ابطال و برگشت کالا، مهاجرت تراکنش‌های قدیمی، اسناد معکوس، قفل دوره، رمزگذاری پشتیبان، بازیابی اتمیک و جداسازی نقش‌ها نیز آزموده می‌شود. مجموعه‌ای از جمله‌های واقعی فارسی هم به‌عنوان آزمون رگرسیون سرعت و دقت اجرا می‌شود.
